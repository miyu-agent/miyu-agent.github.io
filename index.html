测试机是 8 核 16 线程、22G 内存的 Ryzen 7 8745HS。交互速度量了空载和三种压力：CPU 超订是 256 个线程烧 CPU，2000 线程是 2000 个线程每 1 毫秒醒一次，全叠加是整机压满：128 个线程烧 CPU，1000 个线程抢调度，32 个进程不停 fork，32 对线程来回切换，同时还有占内存和写盘的程序，平均负载约 830；cat 是同时开着的最简单的终端程序，当参照，空载为终端去掉按键等待后的复测值。吞吐是 50、200 个会话同时不停地跑；内存是 50、200 个会话各跑 5 轮、歇 10 秒后量的。pi 一个会话一个进程，200 个会话内存不够、开不起来，这两项是推算的：50 个会话时它已用满约 13 个 CPU 线程，10→50 个会话吞吐只从 81 涨到 117 轮/秒，200 个会话也就约 120 轮/秒；内存按 50 个会话的 3.6 GB 乘 4。万轮是一个会话连着跑 1 万轮，按当时上下文的大小分档，量每一步扣掉模型以后各家自己花的时间：跑工具、整理历史、拼请求；dsh 到不了 17 万 token 就压缩了。五家接同一个本地假模型、跑同一套工具调用，比的只是 harness 本身。Test machine: Ryzen 7 8745HS, 8 cores / 16 threads, 22 GB RAM. Interaction speed is measured idle and under three loads: CPU ×16 is 256 threads burning CPU, 2k threads is 2,000 threads waking every millisecond, and all at once saturates the whole machine with 128 threads burning CPU, 1,000 threads fighting over the scheduler, 32 processes forking nonstop and 32 thread pairs ping-ponging, plus programs hogging memory and writing to disk, for a load average around 830; cat is the simplest terminal program, run alongside as a reference, and the idle figure is a retest after the TUI dropped its keypress wait. Throughput runs 50 and 200 sessions at once; memory is measured after 50 and 200 sessions each run 5 turns and sit idle for 10 seconds. pi runs one process per session and runs out of memory before 200, so both of its figures are estimates: at 50 sessions it already saturates about 13 CPU threads, and going from 10 to 50 sessions only lifted it from 81 to 117 turns/s, so 200 sessions lands around 120 turns/s; memory is 4× the 3.6 GB measured at 50. The 10,000-turn test runs one session nonstop and times each step by context size, minus the model: running tools, tidying history, building the request; dsh compacts before reaching 170k tokens. All five use the same local fake model and the same tool calls, so only the harness itself is measured.
